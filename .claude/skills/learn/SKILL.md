# /learn

目的：讓下一集需要修正的地方變少。原則：證據不夠就不立規則；規則由使用者核准；寫下來的規則要具體到下次能照做。

## 1. 收集證據

```bash
python3 scripts/decide.py report            # 全部
python3 scripts/decide.py report --episode <ep>   # 只看這一集
```

再讀 `taste/_me/preferences.md` 全文。需要細節時才去看個別的 `diff.json` 或 `edits.jsonl`。

## 2. 找出三類東西

**規則候選**：同一個 key 的同一種選擇出現 3 次以上，而且出現在 2 個以上的段落。報告裡已標示。使用者明確說「以後都這樣」的不受次數限制。

**數值校正**：修剪數字有穩定方向時，換算成具體的預設值。例如精修時 20 段有 14 段尾巴被收緊、中位數 4 格，表示我留的尾巴比使用者要的長 4 格左右 → 把 `tail_after_last_word_frames` 往下調對應的量。方向不一致（收緊和放長各半）就不是規則，可能和片段類型有關，分開看 `role`。

**矛盾**：新的證據和既有規則相反。不要自己改規則，列出來讓使用者決定：規則要改、要加條件（「只在 B-roll 段」）、還是這幾次是例外。

每一條都判斷範圍：是我的通用習慣（全域），還是只屬於這個 style。同一個習慣在兩種 style 的影片都出現過才算全域；只有一種 style 的證據時先歸在該 style。

## 3. 請使用者核准

把候選整理成清單，每條一行：規則內容、證據（幾次、哪幾集）、範圍。用 AskUserQuestion（可複選）讓使用者勾選要採用的；超過 4 條就分批。使用者可以改寫措辭。

不要提的東西：只出現一兩次的、「已否決」區已經有的、和使用者當下明確指示重複的。

## 4. 寫入

`taste/_me/preferences.md`：

- 採用的 → 對應區塊（全域規則／Style 專屬／數值預設），格式：`規則 —— 證據 N 次（哪幾集），日期`
- 數值校正同時更新該 style 的 `style.json` 對應欄位，並在 `style.md` 加一行註記「依使用者修正調整」
- 否決的 → 「已否決」區，附使用者說的原因
- 被新規則取代的舊規則直接刪除，不留歷史（git 會記得）
- 整份保持在 60 行內；意思重疊的合併

規則的寫法要能執行。「節奏快一點」不行；「口白段每個片段最後一個字之後留 2–4 格，不超過 6 格」可以。

## 5. 回報

- 新增了哪些規則、調整了哪些數值
- 這一集的修正量和上一集相比：對兩集各跑一次 `decide.py report --episode <ep>`，比較對話微調次數、精修時修剪段數佔比、長度變化百分比。這些數字往下走，表示這套流程有在學。
- 提醒使用者 commit：`git add -A && git commit`（只會包含 `taste/_me/`、style profile 與工具本身；每一集的資料夾不進這個公開 repo）
