# /outline

產出只有一份：`EP/work/outline.md`。兩種模式的差別只在起點。

## 先讀（只讀這些）

- `EP/work/footage_map.md`
- `EP/STATE.md`、`EP/episode.json`
- `taste/<style>/profile/style.md` 的「結構」與「節奏」，以及 `style.json` 的 `video_length_s`、`structure`
- `taste/_me/preferences.md`

需要某支素材的細節時讀它的 `summary.md`。需要確切台詞時，請一個 subagent 去逐字稿裡找並只回報那幾句和時間，不要把逐字稿讀進主對話。

## 模式 A：使用者有故事

1. 取得故事：`EP/work/story.md` 或使用者在對話裡的敘述。
2. 拆成 beats（每個 beat 是觀眾得到的一件事）。
3. 做覆蓋表：

   | beat | 可用素材 | 覆蓋 | 說明 |
   |---|---|---|---|
   | 抵達京都 | A003、B011–B014 | 足 | 有口白也有空景 |
   | 迷路 | A007 | 弱 | 只有口白提到，沒有畫面 |
   | 吃到那碗麵 | — | 缺 | |

4. 對「弱」和「缺」各提一個解法：用哪段現有素材替代、改用字卡或地圖動畫、補一句旁白、或拿掉這個 beat。
5. 指出故事本身可以更好的地方，最多三點，例如：最強的畫面放到開場當 hook、兩個 beat 對調、某段素材很好但故事裡沒用到。
6. 使用者確認後寫入大綱。

## 模式 B：從素材提案

提出 2–3 個大綱，彼此的**組織方式**要不同（例如：照時間順序／以一個問題貫穿／從最精彩的一刻倒敘），不要只是同一個結構換順序。每個大綱給：

- 一句話前提
- hook 用哪段素材、為什麼
- 段落列表與各段預估長度
- 這個版本的風險（例如：中段素材偏少）

用 AskUserQuestion 讓使用者選一個或說明要怎麼混合，再寫入大綱。用 `scripts/decide.py log --type ab --key outline-structure` 記下選擇與原因。

## outline.md 格式

```markdown
# <episode> 大綱
前提：<一句話>
目標長度：<依 style.json 與使用者指示>
hook：<哪段素材、哪句話>

## 01-hook
- 目的：<觀眾在這段得到什麼>
- 目標長度：0:12
- 素材：A003 (00:41–00:58 抵達第一句)、B012、B014
- 口白重點：<要留下的句子，一兩句>
- 轉入／轉出：冷開場 → 切片頭字卡
- 未決：<需要使用者決定的事，沒有就省略>

## 02-arrival
…
```

段落名稱用 `兩位數-英文短名`。每段是一個可以獨立粗剪的大 cut，長度建議 30 秒到 3 分鐘；更長就拆開。

## 收尾

- 把段落順序寫進 `episode.json` 的 `sequences`。
- 在 `STATE.md` 的「段落進度」列出每段，狀態為「未開始」。
- 檢查各段目標長度的總和是否落在目標長度內，超出就指出來。
- 下一步：`/cut 01-hook`。建議使用者先 `/clear`。
